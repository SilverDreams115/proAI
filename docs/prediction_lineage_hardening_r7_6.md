# R7.6 — Prediction Lineage Hardening

**Date:** 2026-06-24 · **Branch:** `chore/production-polish` · **Previous HEAD:** `b4b4d0f`
**Scope:** harden the pipeline so that **no future persisted prediction is
left blind**. Does not train, does not recalibrate, **does not backfill** old
predictions.

> Blind historical records are kept intact so as not to alter prior
> evidence. The fix applies to **future** predictions.

## 2. Probable cause

Predictions generated by prior code paths/epochs that (a) did not link
`slate_id`/`composition_hash`, or (b) did not persist the `sanity_audit_json`. There
was no **contract** enforcing traceability before writing, so an incomplete
row was saved silently.

## 3. New lineage contract

New module `app/domain/prediction_lineage.py`:

- `check_prediction_lineage(...) -> LineageCheck` — non-throwing; returns the missing
  fields (for read-only and the audit).
- `assert_prediction_lineage_complete(...)` — raises `PredictionLineageError` before
  writing, with an explicit message `Prediction lineage incomplete: missing <fields>`.

## 4. Mandatory fields (to persist)

```
match_id, slate_id, composition_hash, slate_version, recommended_outcome
sanity_audit_json with:
  raw_probabilities, display_probabilities, decision_probabilities  (non-empty dicts)
  final_status, evidence_level, sanity_policy_version
  model_artifact_id  OR  fallback_used (model lineage)
```

Historical audit rows may also carry an `effective_probabilities` key, written by
the team-rating canary before that subsystem was removed. It was always optional
and nothing reads it any more; its presence or absence is not a lineage gap.

## 5. Where it was integrated

`PredictionService._persist_prediction_audit` (the single point of prediction
persistence in the whole backend — verified by grep). The assertion runs
**after** the non-persistence early-returns (stubs/read-only) and **before**
the best-effort `try/except`, so that a lineage violation **surfaces loudly**
instead of being swallowed as a transient audit error.

## 6. How it fails if lineage is missing

- **Production (persist):** `PredictionLineageError: Prediction lineage incomplete:
  missing <field>` → the blind row is not written.
- **Read-only / non-persistent live:** the compute with `persist_audit=False` never
  reaches the guard (does not persist); `check_prediction_lineage` allows marking
  `lineage_incomplete` in-memory without throwing.
- **Tests:** fails loudly (`pytest.raises(PredictionLineageError)`).

## 8. What was NOT backfilled

- ❌ No historical prediction was modified.
- ❌ `sanity_audit_json`, `slate_id` or `composition_hash` were not filled retroactively.
- ❌ No predictions were regenerated.
- `predictions` delta = **0** (2177 → 2177).

## 9. Mitigated risks

- Future blind predictions (no traceability) → **impossible to persist**.
- Blind error attribution / calibration for new slates → prevented at the root.
- Silent loss of model lineage (artifact/fallback) → blocked.

## 10. Next action

- New predictions (e.g. upcoming active jornadas) will be born with complete
  lineage automatically via the `build_slate_predictions` flow.
- Blind historical ones will remain excluded from the comparable dataset until they have
  results; their lack of sanity_audit is a known limit (documented in R7.4/R7.5).
- **Do not** train or recalibrate until the threshold is reached (≥8 slates / ≥112 matches).
